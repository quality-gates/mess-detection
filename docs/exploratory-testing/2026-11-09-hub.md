The pass registered a cleanup script before running the journeys. It started no background processes, browsers, containers, images, volumes, or listening services. The evidence files retain terminal output; the temporary reports and clone were removed after the journeys.

## Journeys

### Run a native conformance check

A maintainer wants to check a native detector against the shared corpus and retain a complete report. The full Python corpus passed all 61 cases through the `messpy` CLI. The saved report had `complete: true`, 61 results, and no failures. The fixture root was empty afterward. Selecting `control` ran both `control_action` and `control`, and the saved report contained both. Selecting `control_action` alone returned one passing result. See the [native transcript](2026-11-09-evidence/native.txt) and [recovery transcript](2026-11-09-evidence/recovery.txt).

### Correct invalid configuration

A maintainer wants a usage error instead of a detector failure when configuration is invalid. An unmatched quote in `--command` and a `NaN` timeout each returned exit 2 with an argparse error and did not write a report. A corrected native command returned exit 0 with a complete report. These checks cover the symptoms in closed [issue #9](https://github.com/quality-gates/mess-detection/issues/9). The [recovery transcript](2026-11-09-evidence/recovery.txt) records the commands and outcomes.

### Diagnose a failed report and path mapping

A maintainer wants the runner to continue after an unusable native report and explain path attribution. The repository's fake detector returned malformed records for the action twin and calculation. Both cases failed, the runner returned exit 1, and the saved report was complete. The correct fake returned two passes and a complete report on retry. The fake is a runner probe, not evidence of native conformance.

A C#-shaped fake report used `/src` paths. Without a mapping, the action case failed path attribution and the calculation failed because its twin failed. With `--path-map /src=HOST_CHECKOUT`, both passed. No real container or C# detector was used. The [recovery transcript](2026-11-09-evidence/recovery.txt) records both runs and confirms that no fixture entries remained.

## Findings and limits

No new bugs were confirmed. The absent path mapping is expected configuration, not a defect. No unresolved product observations remain from these journeys. The all-state issue and pull request lists showed no open issues or pull requests before the pass. A [tracker snapshot](2026-11-09-evidence/tracker.txt) records a later check. There was no `docs/agents/issue-tracker.md` or `needs-triage` label in this repository, so no tracker-specific triage action applied.

The hub contract test passed six tests. Unittest discovery ran 49 tests with one skip. The [test transcript](2026-11-09-evidence/tests.txt) records both runs. A [verbose corpus run](2026-11-09-evidence/corpus-tests.txt) identifies the skipped TypeScript parser check. CI installs a pinned parser, but the hub has no lockfile for a frozen local installation. The pass checked final report state, not intermediate report updates. The other five native implementations and the reusable GitHub workflow were not exercised end to end. This pass does not establish their conformance.

The runner's `--cases` and `--path-map` instructions are in the status document rather than the README. A reader starting at the README must follow the conformance link to find them. This is an observation, not a confirmed bug.
