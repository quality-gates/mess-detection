# Exploratory test of the mess detection hub

## Scope and starting state

The pass used `origin/main` at `bed69fddfc2cb31e4d3f74aea97726e5b5d4465e` on 2026-11-01. The hub is documentation and a conformance runner, not a native detector. Tests ran in a separate worktree on Linux with Python 3.14.4, Node 22.22.1, and Go 1.26.8. A clean clone of `messpy` at `10ed191955bc0bff9fab6fa4e323938e6701d96c` supplied the public native CLI entry point. The runner used the documented `PYTHONPATH` invocation, so the clone needed no package installation. Fixture data, output files, and the clone lived in the worktree. The hub has no package lockfile for the optional TypeScript fixture parser, so this pass did not install it.

The pass started no background process, browser, container, image, volume, or listening service. A registered cleanup script removed the temporary directory after each shell run. The fixture root was checked after the runner completed. The native clone and JSON reports remained in the worktree until final teardown.

## Journeys and outcomes

### Run the shared corpus against a native detector

A maintainer wants a real detector checked against the documented shared contract. The expected result is one verdict per case and a complete JSON report. The full Python corpus ran against `messpy` with `--fixture-root` and `--output`. All 61 cases passed, the output reported `complete: true`, and no fixture paths remained. A targeted `--cases control` run passed both `control_action` and `control`, as documented. Selecting `control_action` alone passed one case. All three output files remained readable after the fixtures were removed. The [runner transcript](2026-11-01-evidence/runner.txt) includes the commands, verdicts, report counts, and cleanup checks.

### Correct a configuration error

A maintainer wants invalid options distinguished from detector failures. An unknown case produced an argparse message and exit 2, without an output report. Two other invalid options did not follow the documented usage-error contract. Each was repeated twice from a new invocation. The [input replay transcript](2026-11-01-evidence/input-replays.txt) contains the tracebacks and exit codes.

[Issue #9](https://github.com/quality-gates/mess-detection/issues/9) records the confirmed bug. An unmatched quote in `--command` exits 1 with a traceback instead of exit 2. A `NaN` timeout exits 1 with a traceback and leaves an incomplete report with zero results. This can make automation treat invalid configuration as detector nonconformance. The issue contains exact reproduction commands and expected and actual outcomes. Correcting the command to the documented `messpy` invocation succeeded in the native run above.

### Diagnose an unusable detector report

A maintainer wants the runner to record failed cases and finish when the detector is unavailable or returns malformed JSON. With `/missing-detector`, both selected cases failed, the runner returned 1, and the saved report was complete with two failures. With `/bin/echo`, both cases failed on invalid JSON and the runner continued to the second case. The [runner transcript](2026-11-01-evidence/runner.txt) and [input replay transcript](2026-11-01-evidence/input-replays.txt) contain the outcomes. The action twin failure was also attributed to the calculation, as the runner requires.

## Other verification and limits

`python3 tests/hub_contract_test.py` passed all six tests. The [environment and hub test transcript](2026-11-01-evidence/environment-and-hub.txt) records that run and the tool versions. `python3 -m unittest discover -s tests -p 'test_*.py'` ran 45 tests with one skip and no failures. The skip is the TypeScript fixture parser check because the optional TypeScript module was unavailable. The [test output](2026-11-01-evidence/unittest.txt) records the result. The GitHub workflow installs the pinned parser independently; this pass did not reproduce that dependency setup locally without a project lockfile.

The other five native detector implementations and the reusable GitHub workflow were not exercised end to end. The Python run does not establish their conformance. The existing [issue #8](https://github.com/quality-gates/mess-detection/issues/8) concerns fake-detector performance, not the new usage-error finding. The repository had no `docs/agents/issue-tracker.md` or `needs-triage` label at the time of the pass. The new issue uses the existing `bug` label. No prior closed issues were returned by the all-state issue query.

The [decision log](2026-11-01-decisions.tsv) was reconstructed after the experiments. Its timestamps record when the entries were written, not when the experiments ran.

The `--cases` behavior is discoverable in `docs/explicitness-status.md`, but users reading only the README must follow the conformance link before finding the invocation. This is an observation, not a separate bug.
